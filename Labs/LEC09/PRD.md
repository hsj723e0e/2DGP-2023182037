# 소닉 애니메이션 뷰어 개발 요구사항

- 작성일: 2026-10-06
- 기준 문서: `PRE-PRD.md`
- 작업 위치: `Labs/LEC09`
- 개발 브랜치: `feat/lec09-sonic-animation-viewer`
- 구현 파일: `sonic_animation_viewer.py`
- 이미지 파일: `sonic-sprite.png`

## 1. 목적

소닉 스프라이트 이미지에 포함된 모든 캐릭터 동작을 확대하여 순서대로 관찰하는 자동 애니메이션 뷰어를 만든다. 각 동작을 5회 재생하고 1초 동안 정지한 뒤 다음 동작으로 전환한다. 마지막 동작의 정지가 끝나면 첫 동작으로 돌아가 종료할 때까지 반복한다.

추가 요청에 따라 걷기·질주·구르기 등 이동 동작은 프레임 변화와 동시에 화면 위치도 바뀌어야 한다.

완성된 프로그램뿐 아니라 단계별 구현, 확인 결과, Git 커밋을 통해 개발 과정을 확인할 수 있어야 한다.

## 3. 개발 환경 및 파일 구성

- Python 3와 실행 가능한 pico2d 환경을 사용한다.
- 프로그램 로직, 상수, 동작별 프레임 데이터는 모두 `sonic_animation_viewer.py` 안에 작성한다.
- 표준 라이브러리는 사용할 수 있으며, 별도 실행 모듈이나 외부 프레임 설정 파일을 만들지 않는다.
- `PRE-PRD.md`, `PRD.md`, 원본 이미지 같은 문서와 리소스는 단일 코드 파일 조건에 포함하지 않는다.
- 이미지 경로는 현재 작업 디렉터리가 아닌 Python 파일의 위치를 기준으로 계산한다. 저장소 루트와 `Labs/LEC09` 어느 위치에서 실행해도 이미지를 찾을 수 있어야 한다.
- 이미지 로드에 실패하면 원인과 대상 경로를 알 수 있는 메시지를 출력하고 종료한다.

저장소 루트에서 실행하는 명령:

```powershell
python Labs/LEC09/sonic_animation_viewer.py
```

## 4. 스프라이트 분석 요구사항

원본 이미지는 캐릭터 프레임 외에 제목, 제작자 표기, 하단의 다른 캐릭터 그림을 포함한다. 프레임의 크기와 간격도 일정하지 않으므로 전체 이미지를 동일 크기의 격자로 나누는 방식은 사용하지 않는다.

1. 구현 전에 소닉의 모든 동작 묶음과 프레임을 식별한다.
2. 제목, 제작자 표기, 장식용 그림은 재생 대상에서 제외한다.
3. 행을 기본 동작 묶음으로 검토하되, 한 행에 서로 다른 동작이 있으면 분리하고 근거를 기록한다.
4. 동작별 이름, 재생 순서, 프레임 수, 각 프레임의 원본 사각형 좌표를 정리한다. 의미가 불명확한 동작에는 추측한 이름 대신 설명 가능한 임시 이름을 사용한다.
5. 동작 수와 총 프레임 수는 원본 대조 후 확정하여 이 문서에 기록한다. 강의 예시의 수치를 검증 없이 그대로 사용하지 않는다.
6. 프레임마다 캐릭터 전체가 포함되어야 하며, 인접 프레임이나 글자가 섞이면 안 된다.
7. 단일 프레임 동작도 허용한다. 이 경우 해당 프레임을 0.1초 유지하는 것을 1회 재생으로 정의한다.

프레임 데이터는 최소한 `(left, top, width, height)`와 화면 정렬을 위한 기준점 정보를 표현할 수 있어야 한다. 원본 위쪽 기준 좌표를 pico2d의 아래쪽 기준 좌표로 변환한다.

```text
bottom = image_height - top - height
```

모든 프레임은 다음 조건을 만족해야 한다.

```text
left >= 0, top >= 0
width > 0, height > 0
left + width <= image_width
top + height <= image_height
```

| 항목                          | 상태                                       |
| ----------------------------- | ------------------------------------------ |
| 동작 목록 및 동작별 프레임 수 | 아래 원본 분석 목록 참고 |
| 총 동작 수 및 총 프레임 수    | 12개 동작 묶음, 76프레임 (399 × 525 PNG 원본 대조) |

## 5. 기능 요구사항

### 5.1 시작 및 표시

- 실행하면 캔버스를 열고 원본 이미지를 한 번 로드한다.
- 첫 동작의 첫 프레임부터 자동으로 재생한다.
- 원본 프레임의 비율을 유지하여 확대 출력한다.
- 프레임 크기가 바뀌어도 불필요한 좌우 흔들림이나 상하 떨림이 발생하지 않도록 공통 기준점을 맞춘다. 동작 자체의 자세 변화는 유지한다.
- 가장 작은 26픽셀 높이의 프레임도 416픽셀로 출력하여 화면 높이의 절반 이상을 차지한다. 가장 큰 45픽셀 높이의 프레임은 720픽셀로 출력하며, 모든 프레임이 잘리지 않도록 기준점과 화면 여백을 확보한다.
- 매 화면 갱신 시 전체 캔버스를 검은색으로 채우고 현재 프레임을 그린 뒤 캔버스를 갱신한다. 이동 후 이전 위치의 잔상이 남지 않아야 한다.

### 5.2 동작별 반복

- 한 동작의 첫 프레임부터 마지막 프레임까지 각 프레임의 표시 시간을 모두 채우면 1회 재생이 완료된다.
- 1~4회 재생이 끝나면 같은 동작의 첫 프레임으로 돌아간다.
- 5회 재생이 끝나면 해당 동작의 마지막 프레임을 유지하며 정지 상태로 전환한다.
- 프레임 수가 `N`인 동작의 재생 시간은 기본값에서 `N × 0.1 × 5`초이다.

### 5.3 정지 및 동작 전환

- 정지 상태 진입 시점을 기준으로 1.0초를 측정한다.
- 정지 중에도 화면 갱신과 종료 이벤트 처리는 계속한다. 긴 대기 호출로 이벤트 처리를 멈추지 않는다.
- 1초가 지난 뒤 다음 동작의 첫 프레임으로 전환하고 반복 횟수를 초기화한다.
- 마지막 동작 다음에는 첫 동작으로 돌아간다. 이때 이미지 재로드나 창 재생성은 하지 않는다.
- 재생 중 프레임과 반복 횟수가 누락되거나 중복되지 않도록 처리한다.

### 5.4 종료 및 오류 처리

- 재생 중과 정지 중 모두 창 닫기 및 Esc 키로 종료할 수 있다.
- 정상 종료 시 캔버스를 닫는다.
- 프레임 데이터가 비어 있거나 이미지 범위를 벗어나면 실행 초기에 문제 동작과 프레임을 알 수 있는 오류를 표시한다.

### 5.5 이동 및 방향 전환

동작별 기본 이동 속도는 화면 픽셀/초 단위로 지정한다. 동작 이름은 원본의 시각적 설명이며, 다음 분류를 구현 기준으로 사용한다.

| 동작 | 속도 | 표시 규칙 |
| --- | --- | --- |
| 걷기와 몸 낮추기 | 110 | 묶음 전체를 수평 이동 |
| 빠른 걷기 | 180 | 수평 이동 |
| 질주 자세 | 300 | 수평 이동 |
| 구르기 | 240 | 중심 높이를 유지하며 수평 이동 |
| 팔을 굽힌 질주 | 320 | 수평 이동 |
| 낮은 질주 | 360 | 잔상 기준점을 보정하여 수평 이동 |
| 앞을 향한 걷기 | 120 | 수평 이동 |
| 몸 말기, 세로 회전, 옆으로 눕는 자세, 팔 들기, 정지 자세 | 0 | 중앙의 기준점에서 재생 |

- 이동은 실제 경과 시간에 비례하여 처리한다. 프레임이 바뀌기 전에도 위치가 연속적으로 변해야 한다.
- 같은 동작의 1~5회 반복 동안 위치와 방향을 이어간다.
- 각 동작 시작 시 기준 위치 `(600, 80)`에서 오른쪽 방향으로 시작한다. 기준 높이는 `800 / 2 - 20 × 16`으로 계산하며, 회전 동작의 중심은 화면 중앙 높이 400을 유지한다. 다음 동작으로 전환할 때만 위치와 방향을 초기화한다.
- 동작의 모든 프레임 폭과 기준점, 좌우 반전을 고려한 안전 구간을 계산한다. 캐릭터 가장자리와 창 가장자리 사이에 최소 24픽셀 여백을 둔다.
- 경계에 닿으면 반대 방향으로 이동하며, 왼쪽 이동 중에는 프레임을 수평 반전한다. 기준점도 반전하여 캐릭터가 경계 밖으로 밀리지 않게 한다.
- 경계를 넘은 이동 거리를 버리지 않고 반사된 경로에 반영한다. 갱신 간격이 달라도 같은 경과 시간의 위치와 방향이 일치해야 한다.
- 5회 재생이 끝나면 마지막 프레임뿐 아니라 도착 위치와 방향도 1초 동안 유지한다.
- 긴 경과 시간이 정지와 다음 동작을 가로지르면 각 재생 구간에서만 이동하고, 정지 구간에서는 이동하지 않는다.
- 기존 10fps, 5회 반복, 1초 정지 및 50초 전체 순환 규칙을 유지한다.

## 6. 구현 구조 및 시간 처리

단일 파일 안에서 상수, 프레임 데이터, 이미지 로드, 상태 갱신, 그리기, 이벤트 처리, 실행 진입점을 구분한다. `if __name__ == '__main__':` 진입점을 사용한다.

상태는 다음 정보를 관리한다.

- 현재 동작 인덱스와 현재 프레임 인덱스
- 현재 동작의 완료된 재생 횟수: 0~5
- 재생 또는 정지 상태
- 현재 프레임의 경과 시간과 정지 경과 시간
- 화면 기준점 위치 `(x, y)`와 진행 방향 `1` 또는 `-1`
- 동작별 이동 속도와 전체 프레임을 고려한 이동 경계
- 실행 여부

```text
시작 → 첫 동작 재생
재생 → 마지막 프레임 표시 완료 → 완료 횟수 증가
완료 횟수 < 5 → 같은 동작의 첫 프레임
완료 횟수 = 5 → 마지막 프레임으로 1초 정지
정지 완료 → 다음 동작의 첫 프레임
마지막 동작 정지 완료 → 첫 동작의 첫 프레임
모든 상태 → 종료 이벤트 → 캔버스 종료
```

애니메이션 시간은 실제 경과 시간을 기준으로 계산한다. 화면 갱신 횟수로 프레임을 진행하지 않는다. 경과 시간이 프레임 경계를 넘으면 남은 시간을 보존하여 처리하고, 정지 시작 시점을 정확히 계산한다. CPU 사용량을 줄이기 위한 짧은 대기는 가능하지만 재생 시간의 기준으로 사용하지 않는다.
