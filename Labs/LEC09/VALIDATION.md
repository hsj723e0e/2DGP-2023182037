# 소닉 애니메이션 뷰어 검증 기록

검증일: 2026-10-06. 대상: `sonic_animation_viewer.py`.
환경: Windows, Python 3.13.15, 설치된 pico2d 및 SDL2.

## 원본 및 화면

- 원본 PNG 크기: 399 × 525. 소닉 12개 동작 묶음, 총 76프레임.
- 원본을 확대 관찰하고 불투명 픽셀의 경계를 분석했다.
- 모든 소닉 픽셀을 포함하는지 검사했다. 제목, 제작자 표기, 하단 다른 캐릭터는 재생 대상에서 제외했다.
- 첫 행에서 프레임 경계에 섞인 이웃 픽셀을 보정했다.
- 몸 말기 두 번째 프레임의 Y=167 픽셀과 앞을 향한 걷기 네 번째 프레임의 Y=377 픽셀을 포함하도록 보정했다.
- 실제 pico2d 이미지 로드와 76프레임 렌더링을 SDL 가상 화면으로 실행하고, 렌더링 결과 두 장을 육안 대조했다.
- 모든 프레임은 원본 비율을 유지한 4배 출력이며 1200 × 800 화면 안에 들어온다.
- 서 있는 동작은 발 높이를, 회전 동작은 몸 중심을 맞췄다. 낮은 질주는 잔상 폭 때문에 몸이 밀리지 않도록 기준점을 조정했다.
- 초기 버전은 pico2d 기본 격자를 숨긴 밝은 회색 단색 배경으로 검증했다. 28단계에서 배경을 검은색으로 변경했다.

## 상태 및 시간

- 12개 동작 각각에서 5회 재생 종료 직전과 직후를 검사했다.
- 마지막 프레임도 0.1초 표시한 뒤 정지 상태에 들어간다.
- 정지 0.999초에서는 마지막 프레임을 유지하고, 1.000초에 다음 동작으로 전환한다.
- 전환 시 첫 프레임, 완료 횟수 0, 경과 시간 초기화를 확인했다.
- 전체 순환의 논리 시간은 `76 × 0.1 × 5 + 12 × 1 = 50초`다.
- 한 번에 100초를 입력하면 정확히 두 번 순환하고 첫 동작의 첫 프레임으로 돌아온다.
- 큰 시간 입력과 무작위의 작은 시간 입력을 비교해 상태 및 남은 시간이 일치함을 확인했다. 비교한 총 시간: 5.5, 6.499, 6.5, 6.75, 50, 100, 173.456초.
- 단일 프레임 동작도 0.5초에 5회 재생을 끝내고 1초 쉬는 것을 확인했다.
- 음수, 무한대, NaN 시간 입력은 오류로 처리한다.

## 실행 경로와 오류

- 저장소 루트와 `Labs/LEC09`에서 같은 이미지 절대 경로를 계산함을 확인했다.
- 모듈을 가져오기만 하면 창을 열거나 pico2d를 가져오지 않는다.
- 이미지 누락과 읽기 실패 시 경로 및 원인을 안내한다.
- 빈 동작 목록, 빈 프레임 목록, 음수 좌표, 0 이하 크기, 이미지 밖 좌표를 검출한다.
- 재생·정지·전환 상태의 창 닫기와 Esc 이벤트를 모의 입력으로 검증했다.
- 이미지 로드 실패 시에도 캔버스를 닫는다. 정상 종료 시 텍스처를 먼저 해제한다.
- 최종 코드의 Python 문법 검사를 통과했다.

## 이동 추가 전 기본 재생 버전의 실제 Windows 창

실제 창의 1200 × 800 출력 이미지를 확보해 확대, 배경, 표시 위치를 확인했다.

- 기본 재생 루프를 실제 시간으로 실행해 전체 순환을 두 번 완료했다. 실행 및 창 초기화·정리를 포함한 측정 시간: 100.535초.
- 두 순환의 24회 정지에서 최대 정지 시간 오차는 0.0098초로, PRD의 0.1초 이내 기준을 충족했다.
- 모든 전환에서 다음 동작 순서와 반복 횟수 초기화를 확인했다.
- 실제 SDL 이벤트 큐에 창 닫기 이벤트를 넣어 정상 종료와 창 정리를 확인했다.
- 다시 실행한 창의 첫 정지 구간에서 Esc 키 이벤트를 SDL 큐에 넣어 정상 종료와 창 정리를 확인했다.
- 실제 창 검증 프로세스의 종료 코드는 0이다.

## 이동 추가 버전 (25~27단계)

- 7개 이동 동작의 속도는 걷기 110, 빠른 걷기 180, 질주 자세 300, 구르기 240, 팔을 굽힌 질주 320, 낮은 질주 360, 앞을 향한 걷기 120픽셀/초다. 나머지 5개 동작은 이동 속도 0이다.
- 프레임 간격보다 짧은 0.025초 갱신에서 위치가 이동하는 것을 검증했다. 처음 프레임을 유지하는 동안에도 이동한다.
- 각 동작의 5회 재생 이후 정지 구간 0.9초 동안 위치가 정확히 고정됨을 확인했다. 다음 동작에서 중앙 위치와 오른쪽 방향으로 초기화한다.
- 양쪽 경계 1픽셀 안쪽에서 2픽셀만큼 이동하는 입력을 넣어 남은 거리를 반사하고 방향을 바꾸는 것을 검증했다.
- 전체 76프레임을 양방향·양쪽 경계에 놓고 출력 사각형을 검사했다. 좌우 반전 시 기준점을 반영하며 모든 사각형이 24픽셀 여백을 유지한다.
- 6.75, 50, 100, 173.456초의 큰 시간 입력과 무작위 작은 입력을 비교했다. 프레임·동작·상태·방향이 같고, 위치 오차는 0.0000001픽셀 미만이었다.
- 실제 Windows 창에서 첫 동작의 오른쪽 이동, 오른쪽 경계 반전과 왼쪽을 향한 출력, 마지막 프레임의 정지 위치를 캡처했다. 캡처 기준점 X는 각각 700.97, 1115.12, 1027.00이었다.
- 실제 창의 정지 구간에서 위치가 고정됨을 연속 검사하고, 이후 다음 동작으로 전환한 뒤 실제 SDL Esc 이벤트로 정상 종료했다. 검증 실행은 약 7.8초, 종료 코드는 0이었다.
- 초기화 시 잘못된 이동 속도와 유한하지 않은 기준점, 안전 이동 구간에 들어가지 않는 폭도 오류로 처리한다.
- 최초 위치 초기화의 부동소수점 계산 오차는 허용 오차로 비교한다. 정지 중 위치는 시간 갱신 전후 동일 값을 유지한다.

## 검은색 배경 변경 (28단계)

- 초기 화면과 재생 루프에 공통 배경 함수를 적용했다. pico2d의 기본 배경을 지운 뒤 전체 캔버스를 RGB `(0, 0, 0)`으로 채운다.
- 실제 Windows 창에서 오른쪽을 향한 중앙 프레임과 왼쪽을 향한 이동 프레임을 순서대로 렌더링했다.
- 렌더링 픽셀을 읽어 캐릭터 영역 밖의 모든 RGB 값이 검은색인지 검사했다. 네 모서리도 검은색이며 격자와 이전 위치의 잔상이 없었다.
- 캡처를 육안 확인하여 검은색 배경 위에 소닉이 표시되는 것을 확인했다. 검증 프로세스 종료 코드는 0이다.

## 검증 범위

가상 화면 렌더링은 픽셀 경계와 배치를 확인하는 데 사용하고, 실제 창 실행은 실제 시간 및 SDL 이벤트 경로 확인에 사용한다. 종료 이벤트 자동 주입은 물리 키보드 조작과 구분한다. 임시 검증 도구와 캡처는 시스템 임시 폴더에서 실행했으며 최종 프로그램의 실행 의존성에 포함되지 않는다.
